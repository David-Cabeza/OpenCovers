# Conformance status

Audit of the implementation against [conformance.md](conformance.md). Updated as cases are closed.

Status legend:

- **PASS** — the behavior is implemented and covered by a test.
- **PARTIAL** — some parts pass, others are missing or blocked.
- **GAP** — specified in the contract but not implemented.
- **BLOCKED** — depends on email or another external piece that is not yet decided.

| C1 One transaction | **PASS** | GiST exclusion constraint inside the create transaction. Tests: overlap rejected; a new concurrency test asserts two parallel creates yield one booking and one `slot_taken`. Explicit tables must be distinct tables of the venue, else `invalid_request` on create, walk-in and modify (`apps/api/test/known-tables-seat-key.test.ts`). Races between a create, a modify, a cancel and a two-table combination end with no two live allocations of a table overlapping, forced both with one write uncommitted and with both released together (`apps/api/test/overlap-races.test.ts`). Known gaps: when two writes claim one table at the same instant, the loser can get a deadlock error and a `500` where it should get a refusal ([#451](https://github.com/David-Cabeza/OpenCovers/issues/451)), and two writes that claim each other's tables deadlock ([#452](https://github.com/David-Cabeza/OpenCovers/issues/452)). |
