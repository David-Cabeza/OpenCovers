OpenCovers

OpenCovers is an open source reservation engine for restaurants. It handles availability, bookings, tables and a signed event feed. You use it through an HTTP API or an MCP server.

The same engine runs a staff app (agenda, availability, floor plan and setup, in Spanish and English) and a booking widget a venue embeds on its own site, in seven languages (five of them machine-assisted and waiting for native review) and a light or dark look.

Status: pre-alpha. The engine, the staff app and the MCP server run locally and pass their tests, and the booking widget is in progress. 74 of the 83 conformance cases pass and 9 are partial. Allergies and diets (C82) are built in the API and the staff app behind a switch that is off by default, not yet in the MCP tools. Not built yet: payments, SMS and WhatsApp, reminders, a guest screen in the staff app and POS adapters. License: Apache-2.0. Stack: Node.js, Hono, Drizzle and PostgreSQL.

Source code on GitHub

Guarantees

  • One transaction decides availability and booking.
  • PostgreSQL enforces no double booking with a GiST exclusion constraint. Application code does not.
  • Every write carries an idempotency key and produces a monotonic version.
  • Venue data is isolated. A request for another venue returns not found.
  • The engine stores the minimum guest data a booking needs. Erasure returns counts and keeps hashes, not personal values.
  • Webhooks are signed. They push events from the venue's event feed to your HTTPS endpoint.

HTTP API

The API lives under /v1. It is described in an OpenAPI contract. Errors use a fixed vocabulary, listed in errors.md. The contract and its conformance cases come before the implementation. Webhooks are documented separately.

MCP server

The MCP server exposes 18 tools over stdio: reservation.*, waitlist.* and venue.*. It wraps the HTTP API. It is published on npm as @opencovers/mcp and listed in the official MCP registry as io.github.David-Cabeza/opencovers.

npx -y @opencovers/mcp

Create an agent key in the staff app under Setup, API keys. See the MCP contract and the package README.

Run it locally

You need Node.js 22.9 or newer, pnpm and Docker.

git clone https://github.com/David-Cabeza/OpenCovers.git
cd OpenCovers
docker compose up -d   # PostgreSQL
pnpm install
pnpm db:migrate
pnpm dev               # API :3000 · staff app :5173 · site :5174

Open http://localhost:5173, sign up and create a venue.

Roadmap 2027

The goal for 2027: a restaurant runs a full service on software it can read, host and leave, and anyone can check that it works. Today no restaurant runs on OpenCovers.

Three measures track the year. All three are zero today. The goals below are goals, not facts.

  • Venues in service: 0 today, goal 10 by 15 December 2027, at least 3 run by someone other than the maintainer. We call it a miss below 3.
  • Third parties that pass the conformance kit on their own deployment: 0 today, goal 3. A miss below 1.
  • Outside people credited as contributors: 0 today, goal 25, of them 12 with a merged pull request. A miss below 10.

Three named milestones, with goals and no promises: the Double-Booking Trial (goal: 1 March to 30 April, anyone may try to book the same table twice on a public instance with invented data), First Service (goal: June, depends on a legal review and on a venue) and Without the Author (goal: third quarter, depends on a third party).

Dates are goals. A commitment that is missed stays on the board with its cause. It may get one new date, and if it misses twice it is cut in the open.

Read the full roadmap on GitHub or the roadmap on the site (in Spanish). A founding-venue programme is described at opencovers.dev/hoja-de-ruta/#locales-fundadores (in Spanish). To contribute, start with the ten-minute route in CONTRIBUTING.md.
