# CLAUDE.md

Guidance for Claude Code (and any contributor) working in this repository.

## What this is
OpenCovers is an open-source reservation engine for restaurants: availability, bookings, tables and a signed event feed, exposed through an HTTP API and an MCP server. PostgreSQL enforces the no-double-booking rule. Status: pre-alpha. License: Apache-2.0. The project name is provisional (brand review pending, see `docs/cmo-brief.md` §12).

## Setup and commands
Needs Node.js 22+ (`.nvmrc`), pnpm (pinned by `packageManager`, enable with `corepack enable`) and Docker.

```sh
docker compose up -d     # PostgreSQL 16 with `opencovers` (dev) and `opencovers_test` (tests)
pnpm install
pnpm db:migrate          # apply the schema to the dev database
pnpm dev                 # API :3000 · staff app :5173 · site :5174
pnpm test                # integration tests against opencovers_test
pnpm typecheck
pnpm build               # builds apps/web and apps/site (the API and MCP run from source)
```

Single package: `pnpm --filter @opencovers/api test`, `pnpm --filter @opencovers/web dev`.
Other root scripts: `db:up`, `db:down`, `db:generate` (new Drizzle migration), `check:publication`.
Environment variables are documented in `.env.example`; local development needs none.

## Architecture
pnpm workspace (`apps/*`, `packages/*`):

| Path | What | Stack |
| --- | --- | --- |
| `apps/api` | The engine and HTTP API (`/v1`, auth under `/api`) | Node, Hono, Drizzle, PostgreSQL, Better Auth |
| `apps/web` | Staff app (agenda, availability, floor plan, setup) | React, Tailwind, shadcn/ui, TanStack Query |
| `apps/mcp` | MCP server, 18 tools over stdio, wraps the HTTP API | `@modelcontextprotocol/sdk` |
| `apps/site` | Public website at opencovers.dev | React, Vite, Tailwind, static build |
| `docs/` | Contract (`docs/contract`), ADRs, requirements, brand kit (`docs/brand`) | Markdown, OpenAPI |

The staff app dev server proxies `/api` and `/v1` to the API on :3000. Production runs through `compose.prod.yaml` (db + api + Caddy serving the web build); see `docs/deploy.md`.

## Design rules (do not weaken)
- One transaction decides availability and booking.
- The database enforces no-overlap (a GiST exclusion constraint). Application code does not.
- Every write carries an idempotency key and produces a monotonic version.
- A venue's data is isolated: a request for another venue returns not found.
- Store the minimum guest data a booking needs. Erasure returns counts and keeps hashes, not personal values.
- The contract and the conformance cases come before the implementation.

## Conventions
- Conventional Commits: `feat:`, `fix:`, `docs:`, `test:`, `chore:`. One flag (scoped task) per pull request, small diffs, tests with behavior changes.
- A change to the contract needs `docs/contract/openapi.yaml`, `docs/contract/conformance.md` and `conformance-status.md` updated together.
- Decisions that change architecture, contract or security go in `docs/adr/` (start from `TEMPLATE.md`).
- TypeScript strict, ESM (`"type": "module"`). LF line endings (`.gitattributes`), 2-space indent (`.editorconfig`).
- Public docs (README, CONTRIBUTING, contract) are in English. The website copy (`apps/site`) is in Spanish.

## External services
- GitHub: source of truth, CI (`.github/workflows/ci.yml`: typecheck + tests against a Postgres service) and the site deploy.
- GitHub Pages serves `apps/site` at opencovers.dev (`.github/workflows/deploy-site.yml`, runs on every push to `main`). `apps/site/public/CNAME` must stay `opencovers.dev`.
- Cloudflare hosts the DNS for opencovers.dev (DNS only, grey cloud; the apex has the four GitHub Pages A records). Namecheap is the registrar.
- Resend sends confirmation emails (optional; off until `RESEND_API_KEY` is set).

## Do not touch / be careful
- Never commit `.env*` (only `*.example`), keys, tokens or guest data.
- `apps/api/migrations/` is generated by Drizzle (`pnpm db:generate`). Do not hand-edit applied migrations.
- `docs/contract/` is the source of truth; change it deliberately, not as a side effect.
- `apps/site/public/CNAME` and `.github/workflows/deploy-site.yml` control the live site.
- `pnpm test` wipes `opencovers_test`. Never point `TEST_DATABASE_URL` at data you care about.
- Local-only, git-ignored tooling lives in `.opencode/`, `opencode.json`, `.audit/` and `.taste-skill/`. Do not commit them.

## Brand assets
`node docs/brand/build.mjs` regenerates the logo, favicons and social images in `docs/brand/` (needs Chrome or Chromium; set `CHROME=` if it is not found). Edit the script, not the generated files.
